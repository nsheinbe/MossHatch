# reg-gandi - TECH / PRICING verification (adversarial), 2026-09-29

Verifier lens: technical and pricing. Method: independent re-fetch of primary sources (curl with browser UA through the agent proxy; headless Chromium for two Cloudflare-protected helpdesk pages). No account created, no authenticated API call made. The only live API traffic was unauthenticated probes (no token / a dummy token) to read error formats. Raw captures are in `.../scratchpad/research/vgandi-tech/` (api_*.txt = converted API reference pages, d_*.txt = docs.gandi.net pages, p_<tld>_<grid>.txt = price pages, inc.json = status incidents).

Default rule applied: anything not re-checkable against a primary source is "unverifiable". "Confirmed" below means I re-derived it from a primary source I opened myself, and for API behaviour it means "as documented" (nothing was exercised live).

Search budget note: WebSearch was exhausted for the session (200/200), so no searches were run; everything below is direct fetches.

## 0. Bottom line

The analyst's technical and pricing content holds up. Every price I re-fetched matched to the cent, every endpoint row I re-read matched the API reference, and the sandbox/rate-limit claims match. I found no refuted claim. Corrections/qualifications:

1. The multi-year renewal figures (.com A $34.54, E $26.45; .dev A $35.98; .app A $43.18 ...) are shown by Gandi as "Promo Renewal" (struck-through normal price), not a permanent tier. The dossier lists them as plain "2-9y" prices.
2. Autorenew is not "paid from prepaid" only; Gandi's docs say prepaid is tried first, then any saved payment method.
3. DNS writes are not all 200/201: DELETE record returns 204; PUT RRset documents 201; POST 200/201/409; PATCH 200.
4. Error shape: missing-token 401 returns only `{"message": ...}`; a bad/expired bearer returns 403 with the documented `{object,cause,code,message}` shape. Expired token = 403, indistinguishable by status from a scope failure.
5. "No incident touching the six launch TLDs" is too strong: three provider-wide incidents were not TLD-scoped (2025-11-27, 2025-12-16, 2026-07-21) and the 2026-09-07 change_owner incident was "up to 12 hours delay".
6. The domain-list reference still documents `Filtered-Count`, although the changelog (2026-07-27) says it was removed: Gandi's own docs disagree.

## 2. Sandbox / OTE and credentials - confirmed

- Guide https://api.sandbox.gandi.net/docs/sandbox/ (fetched): "you must first create a sandbox account at https://id.sandbox.gandi.net/ and then a Sandbox API key ... not linked in any way to your production Gandi account(s) ... valid only with the Sandbox API"; key at https://account.sandbox.gandi.net/. Authentication page: "for use in the sandbox, the PAT has to be created in the Gandi Sandbox Admin" with link https://admin.sandbox.gandi.net/organizations/account/pat (host answers 301 -> /dashboard).
- Services on sandbox: Domain, LinkedZone, LiveDNS, Billing, Organization, Mailbox (Email API added to sandbox 2025-07-28 per changelog).
- Domain sandbox limits verbatim: "Only a limited set of extension is available: .com .net .org .fr. The Transfer process is not available."
- Sign-up form (id.sandbox.gandi.net/en): email, first/last name, username, password, "I am older than 18 and agree to the General Terms ..." and ToS checkbox; no card or KYC field on the form. I did not submit it.
- Live probes: production and sandbox APIs both answer 401 `{"message":"You must provide an access token or an API Key. See https://api.gandi.net/docs/authentication/"}` without a token; with a dummy bearer both answer 403 `{"object":"HTTPForbidden","cause":"Forbidden","code":403,"message":"Access was denied to this resource."}` plus a `Trace-ID` response header. No rate-limit headers were present on these responses (unauthenticated, so not conclusive).
- Sandbox docs are a mirror: diff of api vs sandbox Domain and Reference pages shows only host names / nav / "SANDBOX" banner differences. The sandbox Organization docs include the reseller flag, customers and release_resellee routes, but behaviour is not proven by mirrored docs (unverifiable: whether reseller orgs, prepaid funding, price grids or expiry simulation work in sandbox).
- Consequence confirmed: of the six launch TLDs only .com is exercisable; .ai/.io/.dev/.app/.studio and all transfer flows are not.

## 3. Rate limits and auth - confirmed

- https://api.gandi.net/docs/reference/: "Gandi's API is rate limited; you can perform a maximum of 1000 requests per minute from the same IP address." Same text on the sandbox reference page. No per-endpoint limits, no 429/Retry-After described for Domain/LiveDNS/Billing/Organization. The only documented 429 in the changelog is Mailbox API (2025-06-05, weekly forward-modification limit). => 429/Retry-After semantics for the Domain API: unverifiable.
- https://docs.gandi.net/en/reseller/faq/index.html: "For users using our classic API, today we rate-limit accounts to 30 requests every 2 seconds. We can facilitate higher levels if needed." (FAQ says "classic API", not explicitly v4/XML-RPC; the dossier's "legacy" reading is reasonable.)
- Auth (https://api.gandi.net/docs/authentication/): `Authorization: Bearer <PAT>`; PAT restricted to resources and "cannot be shared across multiple organizations"; "PATs expire and a token rotation strategy must be considered"; API Key = "Deprecated", unscoped, regenerate-only. docs.gandi.net/en/managing_an_organization/organizations/personal_access_token.html: "Available duration are actually of 7 days, 30 days, 60 days, 90 days or 1 year" (mandatory), scoped to whole org or selected products, per-family permissions. Creation is a UI action ("Create a token"); the API only offers renew: `POST /v5/organization/access-tokens` "generate a new token from the given one, it will copy the current scopes ... renewing a token will not make the previous token expire". Expired/insufficient/unknown bearer -> 403 (documented on every route).
- Error body: documented `{cause, code, message, object}`; I observed exactly that for 403; the gateway 401 for a missing token is only `{"message": ...}`.
- Reference: "POST, PUT and PATCH requests you perform must contain Content-Type: application/json"; sharing_id "for POST, PATCH, or PUT requests that trigger a payment, it indicates the organization that will pay".

## 6. Items the analyst missed or under-reported

1. Changelog: 2026-08-27 LiveDNS `POST /v5/livedns/domains/{fqdn}/verification/{rrset_name}/{rrset_type}` (TXT/CNAME only, "Required scope: dns:domainverify") - a narrowly scoped DNS-challenge write path that could back a least-privilege agent token. Not in the dossier. 2026-07-15 new ACME API (irrelevant to Mosshatch's scope). 2026-06-02 new .au extra parameters. 2025-03-20 DNSSEC routes under /domain/domains/{d}/livedns/dnssec. 2024-04-24 owner update allowed for given/family on company contacts (later narrowed by 2026-01-28 which stops `PATCH /contacts` from touching owner info; owner edits go through `PUT /contacts/owner` or change-owner).
2. Changelog shows no deprecation policy, sunset dates or versioning: breaking changes ship in place (2026-07-27 Filtered-Count/Total-Count, 2026-01-05 Linked Zone limit/offset replaced by per_page/page). The Domain, LiveDNS, Billing and Organization reference pages carry no deprecation notice other than the API-key scheme.
3. Docs contradict themselves on `Filtered-Count`: the changelog says removed 2026-07-27, yet the domain-list and billing-price reference pages I fetched today still list `Filtered-Count`. Code defensively.
4. `state` fields must be UN/LOCODE subdivision codes with a hyphen ("US-MN") (docs.gandi.net/en/rest_api/domain_api/contacts_api.html) - matters for US registrants.
5. The reseller flag can be set via API (`PATCH /v5/organization/organizations/{id}` reseller=true, irreversible; also on create). Onboarding is not UI-only.
6. Autorenew funding: docs.gandi.net/en/domain_names/renew/automatic_renewal.html: "The renewal will first try to use money in your prepaid account ... the system will then use any saved payment methods"; prepaid page: auto-refill from the default saved credit card when balance drops under a threshold. The API has no top-up route (Billing API = info, info/{sharing_id}, price/{type} only - confirmed), but threshold auto-refill is a machine-driven funding path. Billing API also exposes `outstanding_amount` ("payment by terms") and `prepaid_monthly_invoice`, confirming deferred-payment orgs exist.
7. `POST .../restore` documents no Dry-Run header (register, renew, transferin, changeowner do).
8. Every response carries a `Trace-ID` header (observed) - log it for Gandi support.
9. Incident history (https://status.gandi.net/api/v2/incidents.json, 50 incidents, 2025-09-06 to 2026-09-10; status now "All Systems Operational"): 2026-09-07 change_owner "can experience up to 12 hours delay" (PUBLIC API v5); 2025-12-16 "Database incident" (~9 h, emergency maintenance on the main database cluster) listing PUBLIC API v5, Domain name registration, LiveDNS, Billing/payments and ~25 other components (impact "none"); 2025-11-27 "Domain update delayed" (Domain registration + API v5, ~2 h); 2026-07-21 "Domain name availability issue" (~1.6 h); 2026-09-03 delayed 2FA emails; ccTLD-specific outages (.pm/.re/.tf/.wf/.yt 2026-07-29, .cz, .pt, .fi, .as, .tc). Provider-wide dependency risk is larger than the dossier's "none affecting the six launch TLDs".
10. Owner-contact requirements disagree between sources: the register/transferin schema marks only country, email, family, given, streetaddr and type as required (phone, city, zip optional), while the reseller FAQ lists street address, zip, city, country, email, name, phone, contact type and "A password for that account" as mandatory customer data (legacy v4 wording; the v5 docs do not require a password). Validate against Dry-Run: 1 rather than either text.
