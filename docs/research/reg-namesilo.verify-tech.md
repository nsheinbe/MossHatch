## 2. Sandbox / OTE

- CONFIRMED that a sandbox exists and is by request. API reference landing (`https://www.namesilo.com/api-reference`, HTML): "We have an environment that can be used for testing API operations called the "sandbox". To receive a sandbox API account for testing, please contact us and we will get right back to you with your sandbox API credentials." The "contact us" link resolves to `/contact-us` (a form); no email address is given on that page. MCP page (`https://mcp.namesilo.com`): "For sandbox testing, contact support for test credentials" and "Use sandbox mode (ensure "environment": "sandbox" is in the params)". Response code 116 "Invalid sandbox account" is in the code table.
- CORRECTED: the sandbox HOST is not documented anywhere I could read (grep of the reference app bundle, the reference HTML and every operation page: only the sentence above and code 116). The analyst's `https://sandbox.namesilo.com/api/OPERATION` is inferred from a probe. My probe agrees with theirs: `sandbox.namesilo.com` resolves (Cloudflare IPs), `GET https://sandbox.namesilo.com/api/getPrices?version=1&type=json&key=12345` returned HTTP 401 `{"request":{"operation":null,...},"reply":{"code":110,"detail":"Invalid API key"}}`, and `/apibatch/` on the sandbox host returned the same. `https://sandbox.namesilo.com/` root returns 403 (Cloudflare challenge). So a sandbox host that speaks the API envelope exists, but NameSilo has not published its URL; credentials would tell you.
- UNVERIFIABLE: what the sandbox simulates (transfers, expiry, DNS, payments), turnaround time.

## 3. Rate limits

- CONFIRMED: no numeric rate limit is published. I searched (case-insensitive: rate limit, per second, per minute, requests per, throttl, concurrent, quota) every operation page I fetched, the response-code chunk, the reference app bundle, the API Manager article, the API Automated Batch article, the full Terms text (102k chars), the MCP page and the reseller landing page: zero hits. No rate-limit / Retry-After headers on the dummy-key responses (headers captured for both `www.` and `sandbox.` hosts; response is Cloudflare-fronted, `server: cloudflare`, `x-powered-by: PHP/8.4.25`).
- CONFIRMED verbatim (`account-options/api-automated-batch`, curl 200): "Batch use must ONLY use /apibatch for all API calls. The batch API supports all standard API calls and works exactly the same"; "We closely monitor API use and proactively limit batch use in /api ... batch processing calls to /api will be stopped in near real-time ... will in all likelihood result in API and/or account suspension"; monitored signals "Multiple repeated API calls (e.g., multiple attempts of the same operation for the same domain such as multiple transactions for creating domain names)" and "A high ratio of "unsuccessful" to "successful" API responses". Both `/api/` and `/apibatch/` answer with the same JSON envelope (probe: 401 / code 110) on `www.` and `sandbox.`.
- The `registerDomainDrop` page independently says "you must use /apibatch for these operations".
- UNVERIFIED and worth knowing: the MCP marketing page (not the schema) lists methods `getApiUsage`, `getAccountNotifications`, `getAbuseReports`, `dnsUpdateSOA`, `dnsApplyTemplate`, etc. that exist neither in the 51-entry `.well-known/mcp.json` nor in the REST reference. I could not tell whether a usage/quota endpoint exists.
- Auth/transport probes (dummy key) all CONFIRMED: invalid key -> HTTP 401 + envelope code 110; unknown operation -> HTTP 400 plain text `Invalid Request: invalid key`; POST -> HTTP 200 + envelope `{"code":210,"detail":"No route found for \"POST http://www.namesilo.com/api/v1/getPrices\": Method Not Allowed (Allow: GET)"}`; `http://` -> 301 to `https://` with the key in the redirect URL. Code 120 "API key must be passed as a GET" and 112 "API not available to Sub-Accounts" and 113 (IP allow-list) are in the code table. API Manager article: "Users can enter up to 5 IP addresses"; "There is no way to retrieve an already issued API key."
- The API endpoints (unlike the HTML pages) returned JSON to plain curl, not a Cloudflare challenge.

### Basis: what does a reseller / API customer actually pay?

- CONFIRMED: no reseller price list. Reseller FAQ (`domain-manager/reseller-frequently-asked`, curl 200): "There is no special pricing for resellers, but all customers (including resellers), qualify for discounts via the NameSilo Discount Program." Reseller landing page FAQ "How to get better pricing as a reseller": "We offer discounts via the NameSilo Discount Program." The reseller landing page itself advertises the retail order-size tiers ("$17.29 com 1 - 49 domains", "$17.19 ... 50 - 100 domains", "Renewals (1 - 49) - $17.29") and "digressive price rates", not the $11.05 DP number.
- CONFIRMED conditions for the DP 0+ price (`https://www.namesilo.com/discount-program`, headless Chromium, with FAQ accordions expanded): activation is required ("Yes, you need to activate your participation ... from the discount program page or section on your dashboard"); "Discounts apply only when checking out using Account Funds at time of purchase"; "when adding funds, you must add at least $50 each time during your participation ... and for 30 days after cancellation"; "Coupon codes cannot be used while enrolled ... However, bulk order registration discounts will still apply"; tier is by active (unexpired, unsuspended) domains "at the time of the transaction"; 0-99 is "Starter Savings".
- UNVERIFIABLE end to end: that a `registerDomain` / `renewDomain` API call paid from account funds is billed at the DP price. Supporting (not proof): `getPrices` is documented as account-specific with a `retail_prices` override; the DP page says "Drop-catch orders made through our API do not qualify for discounts", which implies other API orders can. Needs an authenticated `getPrices` / `order_amount` check.
- MISSED by analyst (material to margin): DP FAQ "What happens if I cancel": "If you choose to withdraw the remaining funds from your account after opting out, we will refund you the amount minus the discounts you received on your domain registrations and renewals." Pre-funded balance is therefore partly clawed back on withdrawal.
- MISSED by analyst (material to price stability): Verisign's own Form 10-Q for the quarter ended 2026-06-30 (`https://www.sec.gov/Archives/edgar/data/0001014473/000101447326000028/vrsn-20260630.htm`, curl 200) says: ".com ... from $9.59 to $10.26 effective September 1, 2024. On April 23, 2026, we announced that we will increase the annual registry-level wholesale fee for each new and renewal .com domain name registration from $10.26 to $10.97 effective November 1, 2026." With the $0.20 ICANN transaction fee (taken from `tld-registry-facts.md`; I did not re-verify the ICANN fee) the .com at-cost floor moves from 10.46 to 11.17, which is ABOVE NameSilo's DP 0+ price of 11.05 (and above 11.05 even at wholesale only: 10.97 leaves 0.08). Expect NameSilo to raise the .com DP price on or before 2026-11-01; treat 11.05 as a ~5 week price. The dossier's "spread about 0.59" is right for today only.
