# Skeptic verification: stripe-fees (Mosshatch Phase 0)

Verifier lens: skeptic. Date of verification: 2026-09-29. Method: every source below was re-fetched by me on 2026-09-29 through the agent proxy (curl with browser UA; headless Chromium / Playwright for JS-rendered support.stripe.com pages). Raw captures: `working-directory/research/vsk-stripe/` (`*.txt` = text extracts, `calc.py` = my fee recomputation). WebSearch was not usable (session budget of 200 already consumed by the analyst), so the "2026 fee changes" check is by direct fetches of Stripe's own pages only. Mastercard's rulebook and ECP pages returned Akamai 403 to me too (not an egress-policy block); I did not work around it.

## Verdict summary

- Confirmed: every headline number in the formulas (2.9% + 30c, +1.5% international, +1% conversion, +0.5% manual entry, Checkout $0, Apple Pay/Google Pay/Link same as cards, ACH 0.8%/$5 cap/$4/$15), the effective-cost tables (all 5 order sizes x domestic / intl / intl+FX / add-ons / ACH / MoR), refund behaviour, dispute fee behaviour, Visa VAMP thresholds and dates, Stripe's 0.75% line, Radar, Tax, payouts, the restricted-businesses conclusion, the MoR fee schedules.
- Corrected (3): (a) the derived "$40.59 total cash out" for a lost countered $10 dispute double-counts the original 59c (dispute-time debit is $40.00; net loss vs no sale is $30.59); (b) "network programs are unreachable at launch" is true for Visa/Mastercard Excessive tiers only - Stripe's own docs list a Visa "Non-compliant" tier at 5 events / 0.5% that is reachable at launch volume and where Visa "may assess fees"; (c) "never use the Tax API" is wrong above a $100 order (break-even = $0.50 / 0.5% = $100, and the 0.5% base includes the sales tax).
- Unverifiable at a primary source: Visa's $8 per-event fee and 3-month grace (MRC and Chargeflow both say it; Visa's fact sheet does not), Mastercard's own rulebook numbers (only Stripe's description re-checked), Radar migration trial to 2027-01-22, total-vs-component rounding, account-specific dashboard notices, digital-goods dispute base rates.

## 2. Formula and table arithmetic (calc.py, Decimal, ROUND_HALF_UP)

All figures in dossier sections 3.1-3.6 and the tldr were recomputed and match exactly:
- Domestic 2.9% + 30c: $0.59 / $0.74 / $1.03 / $2.04 / $4.65 = 5.90% / 4.93% / 4.12% / 3.40% / 3.10%.
- Intl USD-priced 4.4% + 30c: $0.74 / $0.96 / $1.40 / $2.94 / $6.90. Intl+FX 5.4% + 30c: $0.84 / $1.11 / $1.65 / $3.54 / $8.40 = 8.40% / 7.40% / 6.60% / 5.90% / 5.60%.
- Lost not countered $15.59 / $15.74 / $16.03 / $17.04 / $19.65; lost countered $30.59 / $30.74 / $31.03 / $32.04 / $34.65; Smart Disputes win $18.59 / $20.24 / $23.53 / $35.04 / $64.65; intl+FX lost: $15.84 ... $23.40 and $30.84 ... $38.40.
- Add-ons ($0.05 Radar Standard + 0.5% tax): $0.69 / $0.87 / $1.21 / $2.39 / $5.45; API tax variant $1.14 / $1.29 / $1.58 / $2.59 / $5.20. ACH $0.08 / $0.12 / $0.20 / $0.48 / $1.20.
- MoR table: MP 6.4%+30c $0.94/$1.26/$1.90/$4.14/$9.90; 5%+50c $1.00/$1.25/$1.75/$3.50/$8.00; +1.5% intl $1.15/$1.48/$2.13/$4.40/$10.25; Polar Pro $0.78/$0.97/$1.35/$2.68/$6.10. All match.
- Expected dispute cost table 3.6 matches.

Rounding source (https://support.stripe.com/questions/rounding-rules-for-stripe-fees): "Stripe rounds the Stripe fee to the nearest unit (e.g., cents). For example, if the fee is 0.025, Stripe will round up to 0.03. If the fee is 0.024, Stripe will round down to 0.02." So half-up is supported (half-even would give 0.02).

Implementation trap the dossier does not warn about: in binary floating point 15*0.029+0.30 = 0.735 stored as 0.73499999... and `round(...,2)` gives 0.73 (Python), while Excel/Sheets ROUND (15-digit decimal behaviour) and Stripe (integer cents: 1500 x 2.9% = 43.5 -> 44, +30 = 74) give 0.74. Any Mosshatch code or margin check must use integer cents / Decimal. Also: because the 30c is an integer number of cents, "round total vs round percentage part" is identical for the domestic formula; the total-vs-component question only matters for stacked percentages (2.9% + 1.5% + 1%): at $15 the components would round to 44+23+15 = 82c (+30 = $1.12) versus 5.4% in one step = 81c (+30 = $1.11). Stripe does not say which; unverifiable without an account's balance transactions.

## 3. Refunds and disputes

- https://support.stripe.com/questions/understanding-fees-for-refunded-payments (Chromium): "Stripe's processing fees from the original transaction aren't returned. For businesses on standard pricing, there may be fees when bank transfers are used. For all other payment methods, there are no fees for issuing refunds." CONFIRMED. https://docs.stripe.com/refunds: "You can cancel a payment before it's completed at no cost" CONFIRMED.
- https://docs.stripe.com/disputes/how-disputes-work: "For businesses outside Mexico, the fee for receiving a dispute is non-refundable."; "If you counter a dispute, a dispute countered fee applies, in addition to the dispute received fee ... up to 3 months. Stripe returns the dispute countered fee if you win the dispute. Unless otherwise stated in your Stripe contract, we never return the dispute received fee." CONFIRMED.
- https://support.stripe.com/questions/dispute-fees-faq: "Once a cardholder initiates a dispute, the dispute received fee can't be avoided." "If a dispute is opened after you've fully refunded the payment ... The dispute received fee may still apply." CONFIRMED.
- https://support.stripe.com/questions/june-2025-pricing-updates-for-disputes: counter fee applies "when you counter disputes initiated after June 17, 2025 ... returned if you win"; Smart Disputes waives it; partial win: "The $15 fees to receive the dispute and to counter the dispute will not be returned." CONFIRMED.
- CORRECTION to a derived figure: dossier 3.3 column "Total cash out incl. reversed P (countered)" = $40.59 at $10. Actual balance impact of a lost countered dispute = -P -15 -15 = -$40.00 at dispute time; the 59c original fee was already deducted when the sale settled. Net position vs no sale = -(fee + 30) = -$30.59 (plus any unrecoverable wholesale cost). The tldr's "$30.59 in Stripe fees plus the $10 reversed" is fine only if the $10 is understood as offsetting the $9.41 already received; it must not be added to $30.59 as a loss. Same overstatement in every row of that column ($45.74, $56.03, $92.04, $184.65 should be $45.00, $55.00, $90.00, $180.00 for the dispute-time debit).
- Missed nuance from the same doc: EFW guidance says "optimal point for issuing a refund on early fraud warnings is on charges that are roughly less than or equal to your dispute fee. It's likely not worthwhile to refund EFWs on charges more than 35 percent higher than your dispute fee" (i.e. cut-off about $20 for a $15 fee, not "at or below roughly $15"), and "The only time a refund can prevent a fraud report is when it's processed as a reversal, which usually happens within 2 hours of the payment capture." The dossier's design item that a captured-then-refunded charge "still counts" is right, but a fast reversal is a third path it omits.

## 4. Visa VAMP, Mastercard, Stripe thresholds

- Visa fact sheet PDF (https://corporate.visa.com/content/dam/VCOM/corporate/visa-perspectives/security-and-trust/documents/visa-acquirer-monitoring-program-fact-sheet-2025.pdf, 200, application/pdf, text extracted with pypdf): "Updates to the program thresholds will be effective 1 June 2025"; "VAMP Ratio = Count of [Fraud (TC40) + Disputes (TC15)] / Count of Settled Transactions (TC05)"; acquirer "Above Standard if ... >=50bps and Excessive if >=70bps"; merchant table "AP, Canada, EU, U.S: VAMP Ratio >=220bps; Monthly count of fraud and disputes >=1,500"; footnote 2 "Program advisory period ends 30 September 2025"; footnote 5 "Excessive Merchant threshold reduced to >=150bps in AP, Canada, EU, and U.S. regions on 1 April 2026."; enumeration ">= 2000 bps" and ">= 300,000". CONFIRMED in full. (The fact sheet is a single page and states no fee amounts.)
- Stripe https://docs.stripe.com/disputes/monitoring-programs (accessed today): table "VAMP count: Non-compliant 5 | Excessive 1,500 elsewhere (AP, Canada, EU, US and LAC); VAMP ratio: 0.5% | 1.5% elsewhere"; "Visa assesses fees to merchants that exceed the Excessive threshold and may assess fees to merchants that exceed the Non-Compliant threshold."; EFWs "are considered fraudulent (regardless of their outcome), and Visa's VAMP program includes them"; "Any transaction that appears in both reports [TC40 and TC15] will be counted twice for the VAMP count."; "Visa identifies an account by the static component of its statement descriptor and its acquiring bank." CONFIRMED.
- CORRECTION on "unreachable at launch": the dossier's tldr and design item 6 say both network programs are unreachable. Only Excessive (Visa 1,500 events; Mastercard 100 chargebacks) is unreachable. Stripe's documented Non-compliant tier is 5 events AND 0.5% - e.g. 5 disputes/EFWs on 1,000 Visa payments in a month - which a launch-stage merchant can hit, with Visa "may assess fees". Also a fraud transaction can be counted twice (TC40 + TC15). Because Stripe warns "sudden spike or steep upward trend can trigger placement in a monitoring program before dispute activity reaches the 0.75% threshold" (https://docs.stripe.com/disputes/measuring), the practical alarm level is 0.5% not 0.75%. (The dossier's checklist already uses 0.5% as an internal alert, but its reasoning says the tiers are unreachable.)
- Mastercard (via Stripe docs): ECM "100-299 | 1.5-2.99%"; HECM "300+ | 3%"; fines table (ECM: 0 / 1,000 / 5,000 / 25,000 / 50,000 / 100,000; HECM: 0 / 1,000 / 2,000 / 10,000 / 50,000 / 100,000 / 200,000); EFM ">50,000 USD net fraud volume; >=1,000 e-commerce payments; >0.50%; 3DS <=10%". Re-derived from Stripe's page; Mastercard's own rulebook at mastercard.us / mastercard.com returned "Access Denied" (Akamai 403) to me as well. Confirmed as Stripe's published description only.
- MRC article (https://merchantriskcouncil.org/.../stricter-vamp-ratio-thresholds-are-now-in-effect-heres-how-to-stay-compliant): "April 1, 2026 ... reduction of the 'excessive' VAMP ratio threshold from 2.2% to 1.5%"; "First-time violations within a rolling twelve-month period qualify for a three-month grace period ... Merchants enrolled in VAMP are assessed a fee of $8 per fraudulent or disputed transaction." Chargeflow https://www.chargeflow.io/blog/vamp-visa-acquirer-monitoring-program says "~$8". Both secondary; Visa's own fact sheet states no fee. Treat $8 as unverified at primary.
- Sift https://sift.com/index-reports-disputes-q4-2025/ line: "Under VAMP, the 'excessive' threshold is set at 1.5% starting October 1, 2025, dropping to 0.9% on January 1, 2026, with a $10 fee per disputed transaction". Analyst quote accurate; it conflicts with Visa's PDF, Stripe and MRC (all say 2.2% until 2026-04-01 then 1.5%). Visa preference is right. CONFIRMED as characterisation.
- Stripe "0.75% excessive" + "120 days": https://docs.stripe.com/disputes/measuring - "The credit card processing industry standard recognizes dispute activity above 0.75% as excessive"; "cardholders can dispute a charge up to 120 days after a payment was made (and sometimes even later)". CONFIRMED.
- Digital-goods rates: Chargeflow "0.34% in 2023 to 0.54% in 2024", PayCompass "0.6% to 1.2%" and "Digital Goods 3.62%", Sift "0.26% in Q3 2025" all appear as quoted; none names a dataset. Numbers reproduce; reality unverifiable.

## 5. Radar, Tax, payouts, reserves

- Radar (https://stripe.com/radar/pricing, Playwright, "Show pricing" clicked on each card): Standard "$0.05 per screened transaction ... Includes 200 transactions $0.05 per additional screened transaction"; Plus "$0.07 per screened transaction"; Pro "$0.09 per screened transaction ... $0.005 per additional abuse event"; page text "Radar Lite ... included at no additional charge for businesses on standard payments pricing". https://docs.stripe.com/radar/how-radar-works: "Radar Standard, Plus, and Pro plans charge a fee for each screened transaction." CONFIRMED; the Plus $0.07 / Pro $0.09 rates the analyst rated secondary-only are now confirmed at the primary. Migration trial to 2027-01-22 remains secondary only (corgilabs.ai, section "The January 2027 Deadline") - UNVERIFIABLE.
- Tax (https://stripe.com/tax/pricing and https://support.stripe.com/questions/understanding-stripe-tax-pricing): no-code 0.5% / API 50c CONFIRMED; tiers $90 / $430 / $1,000 / $1,500 CONFIRMED; US registration 0 included, overage $150; US filing overage $55; other countries additional registration $150 CONFIRMED. RESOLVES an analyst 'unverified': "PAYG pricing for Stripe Tax no-code integration is 0.5% of the volume processed, in jurisdictions where you are registered ... This volume includes the complete transaction amount, including any calculated sales tax." So the 0.5% is on the tax-inclusive total. The API price is per Transaction-API call ($0.50) plus $0.05 per Calculation call above 10 per Transaction call. Break-even API vs no-code = $100 tax-inclusive: at a $150 order the API is $0.50 vs $0.75, so "never use the Tax API" is wrong above $100 (the dossier's own table 3.4 shows $5.20 < $5.45 at $150).
- Payouts (https://docs.stripe.com/payouts): "After you successfully receive your first live payment, Stripe typically schedules your initial payout to complete within 7-14 days, depending on your industry, country of operation, and risk level."; "Stripe doesn't charge you a fee to initiate normal payouts."; "ACH Debit 4 business days". Standard 2 business days (support June-2024 Instant Payouts page). CONFIRMED.
- Payout availability delays: charge-level ("delays the payout date for a specific charge that is likely to be disputed for fraud"), "most likely to be used on new Stripe accounts", "released 14 days from the notification date". CONFIRMED (note it is per-charge, not account-wide).
- Reserves FAQ: "The size of a reserve is determined based on the level of risk"; triggers list matches. CONFIRMED. Service terms https://stripe.com/legal/ssa-service-terms: 4.3(a) "Stripe may impose an additional holding period before making the initial settlement to a User Bank Account"; 5.2(a)(i) delay/withhold if "a Dispute is likely to occur"; 2.5 "User is responsible for all Assessed Fines"; sections "Last modified: September 28, 2026". CONFIRMED (not diffed). https://stripe.com/legal/ssa 1.2(a)(ix): "use the Services to conduct a Prohibited or Restricted Business ... unless Stripe has pre-approved ... in writing" CONFIRMED.

## 6. Restricted-businesses conclusion

https://stripe.com/legal/restricted-businesses (200; "Last updated: 2026-09-22"; "Updated credit repair services from prohibited to supportable in the United States."). Full-text grep of the 29k-char page for domain, registrar, registry, hosting, DNS, website, web service, resell, resale, reseller: no occurrence of domain/registrar/registry/hosting/DNS. Relevant lines present: "No-value-added services, including the sale or resale of a service without added benefit to the buyer and resale of government offerings without authorization or added value" (under Unfair, deceptive, or abusive acts); restricted "Sale of stored value or credits maintained, accepted, and issued by anyone other than the seller. Seller-maintained stored value or credits may be subject to limits."; restricted "Payment facilitation and aggregation (including receiving settlement proceeds for goods or services that you did not provide, on behalf of one or multiple third-party sellers)"; prohibited use "Use of Stripe products to facilitate transactions on behalf of another undisclosed merchant or for products or services that weren't disclosed in the business's Stripe account application"; "Evasion of card network chargeback monitoring programs"; IP line "Any other products or services that directly infringe or facilitate infringement upon the trademark ... of any third party". The FAQ (https://support.stripe.com/questions/prohibited-and-restricted-businesses-list-faqs, Chromium, 14.8k chars) has zero hits for domain/registrar/resell/resale. Risk review page (https://support.stripe.com/questions/business-risk-level-considerations-and-evaluation): checks descriptor, product descriptions, contact info, refund/cancellation policy, "how far in advance your customers buy". CONFIRMED. Caveat on the conclusion: absence from the lists is not an affirmative approval; Stripe keeps discretion (reserves, review) and the IP/trademark line plus no-value-added line are the live hooks for a registrar/reseller.

## 7. Checkout capture design

https://docs.stripe.com/payments/place-a-hold-on-a-payment-method: Checkout: `payment_intent_data[capture_method] = manual`; "Usually, an authorization for an online card payment is valid for 7 days" (table: Visa CIT 7 days, Visa MIT 5 days = 4 days 18 hours; Mastercard/Amex/Discover 7 days). Only some methods support this ("Some payment methods that don't support this include ACH and iDEAL"); dynamic-payment-methods doc: "When you set capture_method: manual, some payment methods are automatically filtered out." Monitoring doc line "Issuers are required to report possible fraud for a captured payment, even if it gets refunded, but aren't required to report it for a payment authorization." CONFIRMED. Missed: payment-method mix. Dynamic payment methods show whatever is enabled in the Dashboard, and Klarna (5.99% + 30c), Affirm (6% + 30c) and Afterpay (6% + 30c) cost roughly twice cards; the dossier prices only cards/ACH.
