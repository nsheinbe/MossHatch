## 3. Rate limits

- No numeric XML-API limit anywhere I looked: API overview FAQ "Are there usage limits?" answer (Chromium accordion): "Our infrastructure supports some of the world's largest service providers ... The APIs are built to grow with you." Quickstart, overview, troubleshooting, KB 201000063062/63475: nothing numeric.
- Codes (domains.opensrs.guide/docs/codes.md, updatedAt 2026-06-22): 300 "Exceeded max command rate. Request deferred (for async). or Registration is pending contact agreeing to share information per GDPR."; 310 "Exceeded max simultaneous connections."; 350 "A maximum of 100 commands can be sent through one connection/session"; unnumbered row: "A connection with the OpenSRS server remains open for no more than 60 seconds"; 705 "Timed out, resubmit request." (Note 300 has a second, unrelated meaning the analyst omitted.)
- MSA 3.2 verbatim: "Customer shall use the domain name lookup capability mandated by Tucows in the API or Storefront to determine if a requested domain name is available for registration. This tool may be rate-limited and is a tool used by all Customers; excessive use may result in a fee. Customer explicitly agrees to pay this fee." 12.11: "Excessive use of the domain name lookup tool may result in a fee." Fee unquantified. NEW: the clause also mandates use of Tucows' lookup as the availability authority.
- Other numeric limits confirmed: poll_event max 100 (default 1); submit bulk_change max 10,000 domains, batch.opensrs.net only; get_transfers_away limit up to 40; Storefront JSON API 600 requests/minute per reseller with 429 + X-RateLimit headers (KB 201000127586); WHOIS port 43 1 lookup/second/IP plus an unpublished per-day limit (KB 201000063438).
- IP allow-list: KB 201000063475 "You can have a maximum of five IP access rules"; KB 201000063062 adds "If you need more, contact OpenSRS Support" (so soft cap). CIDR /25-/32, Allow or Deny type; troubleshooting doc: changes take up to 15 minutes.

## 4. Coverage rows (API docs, domains.opensrs.guide, .md versions)

- register (sw_register, updatedAt 2026-03-11): `period` "The default is 2, which is valid for all TLDs" (also "Required for new domain registrations only"); `handle` "lf absent, see reseller setting for default options"; `auth_info` "If provided and valid, the transfer will not send an approval email"; `premium_price_to_verify` required for registry premium; `f_whois_privacy`/`auto_renew` optional with no stated default; response `forced_pending`: "Orders that cannot be processed (insufficient funds, domain already taken, and so on) are forced to the pending queue." No idempotency-key or client-token parameter exists in the attribute table. Codes 485 "Domain taken", 486 "Entity already exists in a processing state (usually a domain registration) Trying again in a few seconds to a minute should resolve the issue", 437 "another request waiting on this domain", 221 "Domain taken (a waiting registration exists in OpenSRS)", 440 "Registration Failed: over quota. Please check for sufficient funds": all verified in codes.md. Note the same insufficient-funds condition is described as both `forced_pending` (sw_register) and 440 (codes); docs do not say when each applies.
- renew (updatedAt 2025-11-11): requires currentexpirationyear, period 1-10, handle. Renew doc code table: 465 "Domain already renewed", 541 year mismatch, and a 400 variant "Domain already renewed; another renewal cannot be applied until the first request completes ... at the registry" plus "Domain is already in 'renewal applied' state" (analyst missed the 400 variants). codes.md also has 555. Premium renewals need `premium_price_to_verify`, documented only on the page with slug `renew-domain_deprecated` titled "Renew (premium domain)" (sidebar: "Renew (premium domain)").
- getDomain (get-domain, updatedAt 2025-11-25): types include all_info, status, registry_dates, domain_auth_info, whois_privacy_state, expire_action, list, waiting history; no type returns EPP status strings (no clientTransferProhibited/redemptionPeriod). all_info "Also returns the fields: auto_renew, expiredate, let_expire, sponsoring_rsp" (no lock_state); type=status returns lock_state, can_modify, domain_supports, transfer_away_in_progress, auctionescrow; type=list extended results also carry lock_state and has_whois_privacy. Page note: "will not return results once a domain is deleted during and after the redemption period". Confirmed.
- setLock: modify data=status with lock_state 0/1, "conditions ... are those for which a get domain status call would return can_modify true". Confirmed. Chart: locking Y for all six TLDs.
- DNS: create_dns_zone, delete_dns_zone, force_dns_nameservers (ns1/ns2/ns3.systemdns.com), get_dns_zone, reset_dns_zone, set_dns_zone. set_dns_zone record types A, AAAA, CNAME, MX, SRV, TXT; fields are subdomain + value only: no TTL, no CAA, no NS. NOT documented: any statement that set_dns_zone replaces the whole zone. Doc says only "Set the records for a domain's DNS zone." KB 201000063118 (RCP): "Applying a template overwrites only the record types defined in that template" and TXT text "up to 254 characters". Storefront-only (Shopco NS) JSON API has per-record CRUD, CAA/NS/DS and TTL (KB 201000127808, 201000127586, 201000131675) but the endpoint list has no register/renew and only works for Storefront domains. No per-record DNS command exists in the API doc index (verified against the 154-page list).
- startTransferIn: sw_register reg_type=transfer + auth_info; check_transfer as pre-check. CONFLICT not flagged by analyst: KB 201000063138 (Transfer Domains into OpenSRS) says "The RWI is the only interface that lets you supply the authorization code with the order itself"; the API reference lists `auth_info`. Same KB: owner approval order "times out after five days"; KB 201000063316 says seven days in one place and five in another (confirms the analyst's 5 vs 7 conflict). Admin email is parsed from the losing registrar's WHOIS; missing/invalid goes to manual holding queue (relevant post-RDP redaction). Horizon cannot exercise this at all.
- getTransfer: check_transfer statuses pending_owner ("If approval is not given within five days, the transfer is cancelled by OpenSRS"), pending_admin, pending_registry ("the transfer completes after 7 days unless it is declined"), completed, cancelled, undef; "Resellers can only request status for transfers that they initiated". NEW: get_transfers_in states "pending_admin has been deprecated". Confirmed otherwise.
- getAuthCode: get type=domain_auth_info ("Returns domain authorization code, if applicable"), send_authcode ("Sends the Authcode for an EPP domain to the admin contact"), modify data=domain_auth_info. KB 201000063434: ".IO" is in the list "Contact OpenSRS Support to obtain auth codes" (.AC .AT .CH .CZ .HK .IO .NU .NZ .PL .SE .SH); KB API section mentions only send_authcode. Confirmed; for .io treat as manual.
- startTransferOut: KB 201000063132: gaining registrar initiates; OpenSRS emails owner approve/decline link; "Owner does not respond within five days" = auto-acknowledge; preconditions unlocked, auth code, no hold, >60 days. API: get_transfers_away (status filter includes pending_owner/pending_registry), get type=status transfer_away_in_progress. No approve/decline command in the transfer command list (cancel_transfer, check_transfer, get_transfers_away, get_transfers_in, process_transfer, rsp2rsp_push_transfer, send_password (transfer), trade_domain). Confirmed no API to approve/decline. rsp2rsp_push_transfer and submit bulk_change (push) exist for reseller-to-reseller moves.
- Pending-order cleanup: cancel_pending_orders requires `to_date` and cancels ALL pending/declined orders up to that date (bulk, not per-domain). process_pending (order_id, command=cancel) is the per-order tool. The analyst's suggestion that CANCEL_PENDING_ORDERS "may" clear a stuck draft renewal should be treated as dangerous/unsuitable.
- Redemption API list (KB 201000063166): .com, .dev, .studio present; .ai, .io, .app absent (parsed 427 TLDs). Confirmed.
- TLD chart values for the six TLDs: grace 40, redemption 30, Auth code Y, Synchronous Y, Domain locking Y, WHOIS privacy Y for .com/.dev/.app/.studio and N for .ai/.io, DNSSEC N for .io only, registry premiums allowed Y for .dev/.app/.studio (group 2 for .studio), N for .ai. Modification log confirms 2025-10-30 ".com grace period changed to back to 40" and 2022-11-28/2023-09-08 .io changes.
- Webhooks (webhooks-overview updatedAt 2026-07-28): HMAC-Signature HMAC-SHA256 hex of raw body with the 36-character secret; Idempotency-Key SHA-256(body); Event-ID; Created-At; 2xx within 5 s; 5xx retried up to 5 times over 24 h; 3xx/4xx not retried; secret resets when URL changes; "As of 2026-07-17, complete these steps in the exact order shown". Event list also includes zone_check_status_change (.de/.fr only), claim_status_change (order), icann_trade_status_change, trust message_status_change (analyst list omitted these; none affects the six launch TLDs).
- Auth: X-Username / X-Signature = md5(md5(xml+key)+key), Content-Type text/xml, XML only (FAQ: "The Domains and Certificates API is XML-based; the Email API is JSON-based"). Sub-users cannot authenticate; regenerating the key invalidates the previous key immediately. Confirmed.
- Vercel Static IPs: https://vercel.com/docs/networking/static-ips (last_updated 2026-06-30): "shared static egress IPs for Pro and Enterprise teams". Confirmed.
