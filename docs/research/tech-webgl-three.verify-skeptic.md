## Recent changes / things the analyst missed (see StructuredOutput.missed)

1. Safari 27 / iOS 27 exist now: caniuse-db (2026-09-28) has ios_saf 27.0-27.2 and safari 27/27.1/27.2/TP columns (iOS 27 usage still 0%); Apple's Safari 27 release notes list only WebGL fixes ("Fixed some WebGL context state properties not being correctly reset on context loss", "Fixed a regression where a WebGL canvas was filled with opaque content that hid stacked canvases beneath it"). No conclusion changes, but the "iOS 26.x = 75.45%" mix will shift and the device matrix should include iOS 27. Safari 26.5 also fixed "WebGL shader compilation to properly handle NaN and infinity values".
2. WebKit's own blog (Safari 26.0 features) says "WebGPU supersedes WebGL on macOS, iOS, iPadOS, and visionOS and is preferred for new sites and web apps." Direction-of-travel signal; does not change the Phase 0 choice because three's ShaderMaterial is unsupported on WebGPURenderer.
3. Canvas readback noise is broader than "known trackers": in WebKit main, Document::noiseInjectionPolicies() adds Minimal when AdvancedPrivacyProtections::FingerprintingProtections is on (or a quirk), and CanvasBase::canvasNoiseHashSaltIfNeeded applies noise if Minimal OR (Enhanced AND script-tracking match); post-processing for non-2D contexts covers the FullBuffer. Apple's public 26.0 text only describes "known fingerprinting scripts". Whether FingerprintingProtections is on by default for normal browsing on iOS 26/27 was not verified. Snapshot path should assert on decoded output rather than assume exact pixels.
4. Chrome Android high-refresh behaviour: Chromium main cc/base/features.cc has kThrottleMainFrameTo60Hz "Enabled on Android, after a field trial showed improvements" (WebView variant disabled by default; an eligibility flag exists that I did not trace). So Chrome Android is likely capped to 60 Hz main frames on 90/120 Hz screens, but WebViews / other engines may run rAF at display rate; an explicit frame cap/skip and refresh-rate-aware controller bounds are prudent (drei bounds switch at >100 Hz).
5. Qualcomm guide also says to prefer alpha blending over discard when combining passes (line 279) while listing blending as an LRZ/Early-Z disabler (line 601); the dossier's "no blending, no discard on full-screen layers" is consistent but the vendor advice is more nuanced (order the blended/discard work late in the frame).
6. Chromium context eviction order is least-recently-flushed, not creation order.
