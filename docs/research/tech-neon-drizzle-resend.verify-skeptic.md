## Missed or changed facts (for the parent)

1. Drizzle 0.45.x migrator applies a migration only if its journal `when` timestamp is newer than the newest applied `created_at` (drizzle-orm 0.45.3 `pg-core/dialect.js` line 62: `Number(lastDbMigration.created_at) < migration.folderMillis`; `folderMillis: journalEntry.when` in `migrator.js` line 22; `drizzle-kit migrate` in 0.31.11 delegates to `drizzle-orm/node-postgres/migrator`). Two PR branches that each generate a migration and merge out of order will silently skip the earlier-timestamped one. 1.0.0-rc.4 replaces this with a name-set difference (`migrator.utils.js` `getMigrationsToRun`) and removes journal.json (the upgrade doc says it "eliminate[s] potential Git conflicts"). This bears directly on the dossier's "pin 0.45.x vs 1.0-rc before the first migration" and the per-PR branch plan.
2. Neon contract and vendor facts (https://neon.com/dpa redirects to https://neon.com/platform-terms; "Product Specific Schedule (Neon)", Last Updated August 5, 2026): the contracting party is Databricks, Inc. ("the parent company of Neon, LLC") under the Databricks Master Cloud Services Agreement; plans auto-renew month to month; "Databricks may make changes to the Agreement, this Schedule, and pricing from time to time, and Customer's continued use ... will constitute consent"; "Customer ... shall not include in Customer Content any cardholder data as defined under PCI-DSS"; the sub-processor list is Databricks' (https://www.databricks.com/legal/databricks-subprocessors, Last Updated June 9, 2026) plus Grafana Labs; the DPA audit clause says "Upon request, Databricks ... will supply (on a confidential basis) the SOC 2 report for the Platform Services and summary copies of the penetration testing report(s)". That last sentence cuts against the dossier's "Launch has no SOC 2 report access": the pricing table gates the Trust Center feature to Scale, but the contract promises the report on request under the DPA. Counsel item: reconcile them. The analyst's "Neon Sub Contractors page not fetched" is answered by this redirect.
3. Neon Launch support level is "Billing support" (plans page); Scale is "Standard". The dossier tabulates it but its design implication ("Launch is the minimum for production") does not flag that a production DB on Launch has no technical support entitlement.
4. Neon role privileges: neon_superuser also carries `pg_write_all_data` and `pg_read_all_data` (roles page). A Console-created role, including `neondb_owner`, can therefore INSERT/UPDATE/DELETE any table regardless of REVOKEs; only the trigger (and not using that role at runtime) protects an audit table, and an owner-created trigger can be dropped by that owner. The audit-table owner should be a SQL-created migrator role, not `neondb_owner`.
5. Neon product changes in the last two weeks (changelog): "Neon backend generally available" 2026-09-18 (Lakebase Postgres branding, Functions with UTC-cron and object-created triggers that "fire even when the compute is scaled to zero", available in aws-us-east-1). This is an option for the outbox worker trigger that the dossier left unverified; runtime limits page not read. Neon SDK moved to v6 with named parameters (breaking).
6. Vercel PrivateLink exists and lists Neon as a target (https://vercel.com/docs/networking/privatelink, docs last updated Sep 15, 2026, read via headless Chromium after the site's own bot check): requires "a team with Advanced Networking enabled", interface endpoints only, not applied to Routing Middleware, connection applies to all environments of a project, endpoint service must be in 2 AZs overlapping Vercel's. Resolves the analyst's "Vercel Functions over Neon PrivateLink" unknown at the docs level (pricing for Advanced Networking not found). Neon side: Scale plan, organization admin only, same AWS region, and a trial can be requested for other plans (https://neon.com/docs/guides/neon-private-networking).
7. Neon root-branch restore: when restoring from another branch, the backup branch "cannot be deleted" and both become root branches (branch-restore page). Relevant to GDPR erasure and to the "restore = audited incident" advice.
8. Resend changes in the last 10 weeks (https://resend.com/changelog): 2026-07-16 GitHub Secret Scanner auto-revokes exposed API keys; 2026-07-08 Message-ID added to all email webhooks and GET email endpoints; 2026-07-28 Email Suppressions dashboard/API; 2026-08-25 Free tier now 3 domains; 2026-09-01 SSO; 2026-09-16 Headless Webhook API. Resend's subprocessor list includes Svix (webhooks), Inngest, AWS, Vercel, Cloudflare, Stripe, Snowflake, PlanetScale and Supabase, so webhook payloads and logs transit more parties than the dossier names.
9. SES default plan for new accounts is Essentials at $0.16 per 1,000 from 2026-07-21 (see row 25).

## Overall

High confidence (about 90%) in the dossier's prices, limits, versions and Postgres/driver semantics: every number I re-derived matched. The corrections are (a) the incident-count framing, (b) the SES headline price, (c) the "no hard cap" statement, (d) the non-verbatim N55 quote, and (e) the SOC 2 gating nuance. The most decision-relevant omission is the Drizzle 0.45.x timestamp-based migrator.
