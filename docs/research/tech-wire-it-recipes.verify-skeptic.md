# Skeptic verification: tech-wire-it-recipes (Phase 4 "wire it" recipes)

Verifier date: 2026-09-29. Method: I re-fetched every source below myself with curl (browser UA, through the sandbox proxy, TLS verification on) and parsed OpenAPI/swagger JSON locally. Raw copies are in `research/vw/` (e.g. `kb_a.md`, `domconfig.md`, `limits.md`, `vercel_openapi.json`, `netlify_swagger.json`, `neon_v2.json`, `rs_*.md`, `np_*.md`, `pb_full.txt`, `rfc*.txt`). No authenticated provider calls were made. WebSearch budget is exhausted (200/200), so recent-change hunting was done through vendor changelogs and doc indexes fetched directly. Vercel returned a "Security Checkpoint" 403 on a few parallel fetches; a sequential retry succeeded (not a policy block).

Overall: the dossier is accurate on essentially every number, date and quote I re-derived. No claim was refuted. Corrections and gaps are listed at the end (Resend domain quota is not "free"; Neon project-scoped keys cannot delete/create projects; DMARC RFC 7489 is now obsolete; .dev/.app are far from the only HSTS-preloaded TLDs; Vercel KB warns about regional reachability of the newer 216.198.79.1 pool).

## Missed or newly relevant facts (not in the dossier)

1. Vercel KB warns that the newer anycast pool address (216.198.79.1) has reported regional reachability failures (Brazil, Oman) and recommends `www` as primary with apex redirect. Combined with Netlify's identical advice, the recipe should default to www-primary for both providers and surface a "apex may be unreachable in some regions" note.
2. Neon project-scoped API keys are Editor-level: no project delete, no project create (see #20). Recipe connection metadata should carry `canCreateProject/canDeleteProject` and refuse `mode: create` or project rollback with such a key.
3. Resend domain quota (Free 3, Pro 10, Scale 1,000; $20/mo add-on for +100) makes `POST /domains` conditionally billable; a `GET /domains` count is a required precondition (see #25).
4. Resend `partially_verified` in the CNAME variant means "sending works, no fallback", not "broken" (see #23).
5. Resend is a GitHub secret-scanning partner since 2026-07-16 (changelog): a leaked `re_` key found in public GitHub content is revoked automatically and admins are emailed. Mosshatch must never write `RESEND_API_KEY` to a repo, and its runtime must tolerate a sudden 401 from a revoked key (re-mint via the stored full_access grant or ask the user).
6. RFC 9989 replaced RFC 7489 for DMARC (May 2026); use tree-walk semantics when reasoning about subdomain sender placement.
7. HSTS-preloaded TLD list is long (see #42); do not hard-code two TLDs.
8. Neon changelog (2026-09-11 "Claimable Neon", 2026-09-18 "The Neon backend is generally available", `neon.ts`/`neon deploy`) shows Neon moving toward an agent-provisioned model with scoped credentials, but scoped credentials do not cover Postgres, so pooled/unpooled URI handling is unchanged. Worth re-checking Neon's partner/OAuth stance before Phase 4 ships.
9. Netlify DNS TXT strings are limited to 255 characters (dns-records.md), a general DNS single-string limit; any registrar-DNS write path that carries long TXT values (DKIM keys, especially if a provider moves to 2048-bit keys) must split into <=255-byte strings. Not sourced beyond that doc line; treat as a design caution.
10. Vercel sensitive env vars are write-only and Preview/Production only; the "restore prior values if known" rollback cannot know prior values of sensitive vars and cannot read them back. Rollback for env changes should be "delete what we created" only.
