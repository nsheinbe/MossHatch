## 7. Things the analyst missed or under-stated (for the missed list)

1. `billing/reseller-balance.json` is documented only for a Sub-Reseller (see section 3); there is no documented API call for our own available/locked balance. Only a dashboard/low-funds email (`fundthreshold`) is documented.
2. `resellers/details.json` (answer/809) documents `Password (password)` and `Personal Identification Number (pin)` in its response field list. Treat that response as secret; never log it.
3. "Order Locked in Processing" is not only insufficient funds; faq1270 also lists "Connection to the concerned Registry could not be established". A timed-out or failed-upstream register can therefore complete later on its own; this strengthens the no-blind-resend advice.
4. Currency and payment mechanics (USD cents/INR Advance Account, LogicBoxes-set FX, card surcharge, sign-up-time currency choice) affect wholesale cost basis.
5. Vercel arithmetic: one Static IP pair (2 IPs) per region vs the 3-IP self-serve cap; a second region needs a support request. Static IPs do not apply to middleware/edge functions; builds can also route through them.
6. Premium names are truly zero-margin (same price for reseller, sub-reseller, customer).
7. DNS activation only for orders whose Customer sits directly under the reseller (faq580).
8. Register response omits the charged amount when `invoice-option=NoInvoice`, so per-order wholesale cost must be read from transactions or the cost-price cache.
9. `reseller-cost-price.json` payload includes all hosting/web products ("huge number of products") and the KB says it may cause "longer wait time than usual": fetch off the request path (background job into Neon), not in a serverless request.
10. Transfer-in doc lists `.AU .CA .DE .EU .NZ` as compulsory-auth-code TLDs but its separate "required" list omits .AI/.IO/.DEV/.APP; treat both lists as stale and always send the code for our six TLDs.
