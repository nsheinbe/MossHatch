### DNS record CRUD - CONFIRMED replace-all; TTL floor CORRECTED
- Transcription setHosts: HostName[1..n], RecordType[1..n] (A, AAAA, ALIAS, CAA, CNAME, MX, MXE, NS, TXT, URL, URL301, FRAME), Address[1..n], MXPref[1..n], EmailType (MXE, MX, FWD, OX) Required, TTL[1..n] "(300-60000)". No add/update/delete single-record method exists.
- SDK README (Namecheap org): "SetHosts ... is the only write endpoint the API offers, and it replaces the entire record set ... forget one and it is silently deleted"; "The API is not transactional ... lost update". KB FAQ: BIND import unsupported, "use setHosts command"; PremiumDNS/FreeDNS domains cannot be managed via API. WHMCS lists DNS Record Management Y (via get/setHosts).
- TTL conflict: transcription says 300-60000, but the SDK's own validation constants are `MinTTL = 60`, `MaxTTL = 60000` (namecheap/domains_dns_set_hosts.go) and the SDK treats 1799 as the "automatic" TTL. The analyst listed TTL minimum as unverified; the accurate statement is "two Namecheap-authored sources disagree: 300 vs 60".
- Namecheap MCP exposes per-record dns_records_save/delete ("Add DNS records or update their TTL"), implying Namecheap has record-level logic internally, but the public XML API does not.

### getDomain (`getInfo`, `getRegistrarLock`, `getList`) - CONFIRMED no registry EPP statuses
- Transcription getInfo: Status "OK, Locked, Expired"; DomainDetails Created/Expired (MM/DD/YYYY), Whoisguard, DnsDetails, Modificationrights; note "getInfo has no domain-level auto-renew field"; getList carries IsExpired, IsLocked, AutoRenew, ListType ALL/EXPIRING/EXPIRED.
- Namecheap's own MCP Tools Reference (KB 10824) for domains_list: "eppStatuses - Not reported by Namecheap - empty"; "suspensions", "verificationStatus" likewise not reported; single-domain lookup returns autoRenew null. So registry statuses (redemptionPeriod, pendingDelete, serverHold, clientHold) must come from RDAP. KB 10064 confirms expired names "will be removed from the Domain List and will enter the Redemption Grace Period".
- Nuance: the MCP schema enumerates `lifecycleStatus` = creating | registered | grace1 | redemption. The page does not say which of these Namecheap actually populates, so I do not treat it as contradicting "RGP domains vanish from the list", but it is worth a sandbox test.

### register (`domains.create`): idempotency / duplicates
- No idempotency key in the parameter table (transcription lines ~130-175). SDK README: create/renew/reactivate "are treated as non-idempotent: on an ambiguous transport or server-side failure the SDK does not retry (a resend could double-charge); only Namecheap's pre-execution HTTP 405 rate-limit signal is retried. Reconcile such failures via the account order history." CONFIRMED.
- Independent Namecheap-authored corroboration in the MCP reference: a `failed` domain_register whose note "says the outcome is unknown ... the charge may or may not have gone through, so do not blindly resubmit ... until domains_list shows the domain is not registered." Even Namecheap's own gateway uses a confirmation token (argument-bound) rather than a server-side idempotency key.
- Duplicate / already-registered error code: none in the transcription or SDK sentinels (the documented sentinels are 2019166, 2016166/3016166, 2030166, 2011169, 2011170, 2033409, 4011103, and server codes 3050900/5019169/5050169/5050900). UNVERIFIABLE (analyst's "unverified" stands).
- CORRECTION on "Synchronous": KB FAQ says "Domain registrations are real time through the API", but `getTldList` returns `NonRealTimeDomain` ("indicates whether registration is instant"; the SDK's create fixture also carries a NonRealTimeDomain attribute), and the MCP reference defines `status: pending` = "Submitted; the registry is still finishing. Call domains_list shortly to confirm". The adapter must handle a non-instant path for some TLDs (which ones is unknown).
- Other create facts re-confirmed: Years default 2 (max 2 digits), Registrant/Tech/Admin/AuxBilling all required, AddFreeWhoisguard default Yes, WGEnabled default No, IsPremiumDomain+PremiumPrice, PromotionCode, response ChargedAmount/OrderID/TransactionID/DomainID.

## 3. Rate limits - CONFLICT CONFIRMED, authoritative number UNVERIFIABLE
- KB 9739 ("What are your API limits?"): "Our general API calls restriction is 50/min, 700/hour, and 8000/day across the whole key."
- Namecheap-org Go SDK: "Namecheap documents 20 requests/minute, 700/hour and 8000/day" (README "Rate limiting & retries"; transport.go `defaultPerMinute = 20`, comment "Namecheap's documented primary quota of 20 requests/minute"). Namecheap-org Terraform provider docs/index.md: `requests_per_minute` "Must be between 1 and 20 (Namecheap's documented primary quota). Defaults to 20"; ci-environments.md: quota enforced "at the account level".
- Hour (700) and day (8000) agree in both; only the per-minute figure conflicts (50 vs 20), and scope differs ("key" vs "account"). The API intro page that both presumably cite is unreadable. Plan for 20/min (analyst's advice is right).
- HTTP 405 as the throttle signal comes only from the SDK (transport.go: "responds with HTTP 405, which Namecheap uses to signal rate limiting ... Namecheap returns 405 before it processes the request"). Not in KB. Treat as Namecheap-maintainer knowledge, not documentation.

## 7. Items the analyst missed or under-weighted
1. `NonRealTimeDomain` flag (getTldList) and MCP `pending` status: register is not guaranteed instant.
2. Namecheap's own MCP gateway can set auto-renew as a separate post-registration step and read a `lifecycleStatus` (creating/registered/grace1/redemption): Namecheap has internal capabilities beyond the public XML API. getInfo `Modificationrights` also lists rights types `autorenew` and `dnsSec`. Ask Namecheap whether an API (v3/REST) exists for these.
3. Docs incompleteness: whoisguard.allot/unallot/discard exist but are undocumented (SDK CHANGELOG). Use written confirmation from Namecheap rather than sitemap-absence to close getAuthCode.
4. TTL minimum conflict 60 (SDK code) vs 300 (docs transcription).
5. DNSSEC: exists but UI-only (Advanced DNS > DNSSEC toggle for BasicDNS/PremiumDNS; manual DS entry for custom DNS; KB 9718/9722/9723). Unsupported-TLD list (.africa .barcelona .cat .cm .com.sg .de .eu .nl .ph .sg .so .com.au .net.au .org.au, Handshake) does not include the six TLDs. No API method.
6. UI bulk auth-code retrieval for transfer-out (KB 10630) is a workable operator runbook; expired domains cannot be unlocked without Support; UI bulk transfer-in is capped at 50 domains per order.
7. .ai first-purchase and every renewal are >= 2 years of cost; there is no 1-year .ai line item (see section 4).
8. Vercel Static IPs are a shared pool (small group of customers per region) and the docs do not say IPv4.
9. Rate-limit scope differs ("whole key" vs "account level"), and the 405-on-throttle behaviour is SDK-only knowledge.
10. `getList` PageSize default is 20 (min 10, max 100) - trivial but the analyst's summary omitted the default.
11. Error codes reference "Enom" upstream (3031510 "Error response from Enom", 3016166 "not associated with Enom") - the API backend has an upstream-registrar heritage; KB 1420 says the redemption fee is "set by our upstream Registrar and Domain Registry". Worth one written question about who the sponsoring registrar is for each TLD and whether an upstream can change terms.
