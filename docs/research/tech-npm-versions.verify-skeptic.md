## Facts the analyst missed or under-weighted

A. npm has moved on and the analyst tested only npm 10.9.7. `npm view npm dist-tags`: `latest` = 12.1.0 (12.0.0 released 2026-07-08, 12.1.0 on 2026-09-22; engines `^22.22.2 || ^24.15.0 || >=26.0.0`), `next-11` = 11.20.0. Node 24.21.0 and Node 26.10.0 bundle npm 11.19.0 and 11.19.1.
B. npm 11.19 and 12.1 block dependency install scripts by default. The bundled docs (`npm-install-scripts.md`, Node 24.21.0) say "Dependency install scripts are blocked by default. Install commands silently skip lifecycle scripts for any dependency that does not have a matching entry in `allowScripts`", and `npm ci` printed "3 packages have install scripts not yet covered by allowScripts: esbuild@0.28.2, esbuild@0.25.12 (x2)". In the recommended set the packages with install scripts are esbuild (x3 copies), fsevents (macOS only); the all-latest set adds protobufjs. Everything still passed with scripts blocked (esbuild falls back to its platform binary package), so the conclusions hold, but the scaffold should decide on an `allowScripts` policy, and CI on Node 24 will emit these warnings. This is a supply-chain positive.
C. Vercel's docs (https://vercel.com/docs/package-managers.md, last_updated 2026-08-11) map only Node 20 and 22 to npm 10; there is no row for Node 24, so which npm Vercel uses for Node 24 builds is undocumented (docs say npm's default "aligns with the Node.js version"). Also Vercel's default install for `package-lock.json` is `npm install`, not `npm ci` (https://vercel.com/docs/functions/runtimes/node-js.md, "Node.js dependencies"). The dossier's "use npm ci" is CI advice only; for Vercel deployments set `installCommand` to `npm ci` if lockfile-exact installs are wanted.
D. Vercel's own TypeScript handling. `@vercel/node` 16.0.2 (`dist/index.js`) resolves the project's `typescript`; if that module lacks the legacy JS API it switches to `registerNativeCompiler`, which spawns the `bin.tsc` from that package's package.json (native TS 7). With the analyst's alias layout, `typescript` resolves to `@typescript/typescript6` (legacy API path), so both layouts are handled by that builder version. Docs add that `tsconfig.json` is honored except path mappings and project references. Which builder version Vercel runs in production is not visible to us.
E. Node 24 and Node 26 execution (listed as unverified by the analyst) is now verified for the toolchain: Node 24.21.0 and 26.10.0 official binaries (sha256 matched nodejs.org SHASUMS256.txt) ran tsc 7, tsc6, vite build, vitest, eslint, size-limit, drizzle-kit generate with no failures. Still not exercised: live services and a real Vercel deployment.
F. Vercel Node 20 escape hatch `VERCEL_ALLOW_DISCONTINUED_NODEJS20=1` (2026-11-01), see claim 20.
