## 1. What Mosshatch is

A domain reseller at https://mosshatch.com, invite-only for now. People search a name, pay on Stripe, and the name registers at
Openprovider (the registrar of record). Each name "hatches" a creature in a 3D grove. The site is also an MCP server, so Claude and
other assistants can search names, manage DNS and run recipes (Vercel, Resend, Neon) for the owner, behind a passkey for anything
that costs money or touches sensitive records. The first live purchase, untilwow.com, happened on 2026-10-08.

## 3. How to work on it

```
npm ci
bash scripts/pg-local.sh start      # local Postgres on 127.0.0.1:54329 for the tests
npm run typecheck                   # every workspace
npx vitest run                      # ~1500 unit and integration tests, needs the local Postgres
npm run build                       # production build; fails if the bundle budgets are exceeded
npx playwright test                 # the full browser suite, 80+ tests, 20 minutes; project filters: --project=account etc.
node scripts/check-st-ids.mjs       # every security test id is scheduled
```

Conventions that CI or the owner will enforce:

- One branch per piece of work, a draft pull request, CI green, squash merge, then confirm both Vercel production deployments are
  READY and spot-check the live site. The owner's standing instruction is "merge it and let me know when it's live".
- Commit messages and pull request descriptions say what changed and why, in plain words. No model names in anything committed.
- Initial JavaScript budget: 110 kB gzip target, 130 hard. It is at 109.0. New UI goes in lazy chunks (see `App.tsx` for the pattern).
- The store (`apps/web/src/store/index.ts`) persists only `calm`, `sound` and `rehideSeconds`. Nothing fetched or secret is persisted.
- Every new screen must pass axe (WCAG 2.2 AA); the browser specs call `clean(page, ...)`.
- Names typed by people never appear in a request URL or a server log (AUDIT-2026-10-07 V1). Searches POST the name in the body;
  buy links carry it in the URL fragment (`/#find=name.com`).
- Emails to the owner about an agent's request never contain a link (threat model row 43, `docs/PLAN.md`; enforced by
  `packages/api/src/agents/session.test.ts`). They say where to look instead.
- The legal documents under `apps/web/public/legal`, plus `fees.html`, `security.html` and `commitments.html`, are versioned by
  file hash (`packages/api/src/account/documents.ts`). Changing them, including the shared nav that `scripts/render-public-pages.mjs`
  stamps in, publishes new versions through the go-live-db workflow. Do not touch them incidentally. `commitments.css` is not versioned.
- Every route that accepts a bearer token must have an entry in `packages/api/src/bindings/scope-matrix.test.ts` (ST-65).
- Vercel preview deployments have no database: the API answers 503 `not_configured` there. Verify API behaviour locally or on production.
- Never echo customer data (registrant name, email, phone, address) from a database query into a chat, a log or a file.

## 6. Things that will trip you up

- CI starts two identical runs per push. A failure on an old commit after you have pushed a fix is expected; only the newest head counts.
- The first requests to a brand-new production deployment can 502 on static assets for a few seconds (CDN cold cache). Retry before
  concluding anything.
- The arrival demo on the home page types "moonfern" 1.5 seconds after load on a first visit; anything that pre-fills Find must set
  `demo: "done"` in the store (see `takeFindLink` in `App.tsx`).
- `scripts/render-public-pages.mjs` regenerates every public page. Run `npm run pages` after editing `apps/web/pages/*.html` and
  check `git status` shows only the pages you meant to change (the legal ones are versioned, see section 3).
- `vercel.json` rewrites: every API path must be listed (`/mcp`, `/mcp/search`, `/.well-known/...` are). A new top-level API path
  needs a rewrite or Vercel serves the SPA instead.
- The scope grammar is `capability:resource[:env]`; `register.propose` is star-only; env `*` never covers `prod`;
  `secrets.read:*:prod` is refused. `packages/api/src/bindings/scopes.ts` is the source of truth, and the web's everyday choices in
  `apps/web/src/lib/scopes.ts` are checked against it by `bindings/choices.test.ts`.
- Recipes need a provider token pasted once per name on the Connect tab. Vercel tokens must be team- or project-scoped; the recipe
  picks the team itself. Plans expire after one hour and are bound by hash; approve with the passkey (`dns.sensitive.approve`).
- Pausing a token (`POST /api/v1/bindings/:id/pause`) needs no passkey; resuming is `agent.token.widen` with the same scopes and does.
- The invite-only gate (`requireLiveAccess`) makes anonymous `/api/v1/search` answer 403; the public MCP search therefore uses the
  RDAP preview lookup and published prices until the shop opens, then switches to the registrar automatically.
